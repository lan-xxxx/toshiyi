## 背景和用户场景

曾皙反馈：在 Web / iOS 日常同时处理很多群聊和私聊时，相邻会话之间视觉区分不够明显，影响快速扫视、定位当前会话，并可能增加误点概率。

## 问题陈述

当前会话列表在高密度、多会话混排场景下，相邻 item 的边界和状态层级不够清晰。用户需要在群聊、私聊、未读、@我、当前会话之间频繁切换时，视觉识别成本偏高。

## 目标

- 提升 Web / iOS 会话列表相邻会话的可区分度。
- 降低多群聊/私聊并行处理时的扫视成本和误点概率。
- 在不显著增加信息噪音、不破坏现有信息密度的前提下增强视觉层级。

## 默认方案

1. 增强会话 item 之间的分隔线或背景层级。
2. 强化当前选中会话的 active 状态。
3. 强化未读 / @我 状态的视觉优先级。
4. Web 侧补齐 hover / active 态一致性；iOS 侧保证触控区域和视觉反馈清晰。
5. 暂不默认重做群聊/私聊图标体系，避免引入过多视觉噪音。

## 覆盖范围

- Web 会话列表。
- iOS 会话列表。
- 群聊 / 私聊混排、高会话密度、浅色/深色模式。

## 验收标准

- 连续 20+ 个会话混排时，相邻 item 边界可明显识别。
- 当前选中会话、未读会话、@我会话状态清晰可区分。
- 不降低原有会话列表信息密度和可点击区域。
- 浅色/深色模式均满足可读性。
- 设计 review 通过后，Web / iOS 前端 review 通过。

## 非目标 / 边界

- 本期不调整会话排序、会话分组、消息同步逻辑。
- 本期不默认新增群聊/私聊强图标体系，除非设计 review 判断必要。
- 本期不涉及服务端逻辑变更，除非前端实现发现现有字段不足。
